# M1 repository findings and deviations

The M1 task file is authoritative over the broader `IMPLEMENTATION.md` phase plan. These findings describe this checkout as of 2026-10-14.

| Plan assumption                                                                      | Repository finding                                                                                                                                                                                           | M1 consequence                                                                                                                                                                           |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The preload lives under `src/ipc/preload`.                                           | The bridge is `src/preload.ts`; `src/ipc/preload/channels.ts` defines its invoke/send/receive contract.                                                                                                      | The web bridge imports the actual contract and keeps the `window.electron.ipcRenderer` / `webFrame` surface.                                                                             |
| The browser communicates through a simple invoke bridge.                             | IPC includes envelope semantics, dynamic terminal receive channels, and a distributed chat actor transport.                                                                                                  | The web bridge and RPC event proxy preserve envelopes, generated terminal events, and session IDs; the gateway denies channels outside its contract policy.                              |
| A desktop main bootstrap can be reused headlessly.                                   | `src/main.ts` initializes Electron lifecycle, telemetry, native modules, OAuth, and desktop services.                                                                                                        | The runtime has a separate headless entry at `src/web/runtime_main.ts`; it does not run desktop startup.                                                                                 |
| Local app path validation establishes a workspace boundary.                          | Existing helpers validate individual app paths but do not establish the browser runtime's workspace root.                                                                                                    | The RPC path guard validates app ownership and resolves guarded paths below the configured workspace root.                                                                               |
| Every filesystem RPC argument has a uniform shape.                                   | IPC handlers have channel-specific argument and payload shapes.                                                                                                                                              | The current path guard uses an explicit channel/argument map plus app ID ownership validation; additional path-bearing channels need coverage before hosted exposure.                    |
| Preview URLs can be sent through unchanged.                                          | Renderer preview state compares several URLs by origin; local preview apps need distinct hostnames and the gateway must own target resolution.                                                               | Runtime URL rewriting uses app-specific hostnames; the gateway obtains loopback ports from an authenticated runtime endpoint. Production preview-token behavior is not browser-verified. |
| The gateway and control plane already exist.                                         | This checkout had no gateway package, authentication/session proxy, or configured database service. M1 adds a NestJS gateway and an optional Prisma-backed store; local development defaults to JSONL files. | Gateway tests use local stubs. PostgreSQL persistence and hosted deployment were not exercised.                                                                                          |
| Model-provider requests may be logged for diagnostics.                               | Prompts and completions contain user project data and provider credentials are server-side secrets.                                                                                                          | The model gateway records token/latency metadata only; it does not log prompt or completion bodies.                                                                                      |
| Verifier commands can be accepted as arbitrary shell strings.                        | Model-supplied shell commands would create a separate execution surface.                                                                                                                                     | M1 does not implement the broader phase-plan verifier or arbitrary command API.                                                                                                          |
| Container resource and egress controls can be supplied portably by application code. | CPU, memory, process count, bind mounts, and network egress depend on the deployment host/orchestrator.                                                                                                      | `runtime/README.md` documents the deployment requirements. No orchestrator enforcement was exercised in M1.                                                                              |
| Runtime Node and Electron can share the root native-module install.                  | Native modules may be built for a different Node/Electron ABI.                                                                                                                                               | `runtime/native` owns pinned Node builds; an explicit resolution hook keeps the web runtime from resolving those modules from the root. Both ABI checks passed on Windows.               |
| Desktop global Git trust settings are safe to mutate at web startup.                 | A web runtime should not change the host user's global Git configuration.                                                                                                                                    | The web bootstrap skips the desktop global `safe.directory` mutation.                                                                                                                    |
| M1 needs additional imports from `src/pro`.                                          | Search of `src/web` and `src/ipc` found no direct imports from `src/pro`.                                                                                                                                    | No new `src/pro` imports were added by M1. The runtime's transitive bundle dependency graph was not exhaustively audited.                                                                |
| The app's native folder picker maps to a browser operation.                          | The existing import handler accepts a host filesystem path; no bounded ZIP upload API exists.                                                                                                                | Folder/ZIP import remains unavailable in web mode and must not be treated as implemented.                                                                                                |

The working directory has no `.git` metadata, so the original checkout state and a final file-level Git diff cannot be independently verified. The repository-root `userData/` directory was excluded from snapshot collection and was not inspected.
