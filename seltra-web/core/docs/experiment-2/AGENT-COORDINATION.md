# Experiment 2 agent coordination in Dyad

## Runtime boundary

The existing Dyad local-agent loop remains the only application-editing runtime. Root turns, tools, file writes, build/runtime lifecycle, preview, consent, Git snapshots, and repair continue through `src/pro/main/ipc/handlers/local_agent/` and the established app/chat operation coordinators. The embedded Seltra runtime is a read-only source of ideas; none of its Next.js builder, API, database, Cloudflare sandbox, or orchestration runtime is imported or launched.

## Experiment 2 task/artifact contract target

Future artifacts should be per-turn, versioned, bounded records with `runId`, `artifactId`, `schemaVersion`, `createdAt`, `producer`, `modelId` (when known), `status`, `content`, and a provenance reference. Minimum content shapes:

- `BusinessBrief`: business, audience, goals, entities, journeys, constraints, and unknowns.
- `RequirementsSpec`: acceptance criteria and covered/unsupported dispositions.
- `ImplementationPlan`: ordered tasks, dependencies, and conflict/writer scope.
- `DesignSpec`: brand/audience, page hierarchy, page-specific composition, typography, palette, spacing, art direction, responsive behavior, accessibility, interaction states, anti-patterns, and testable criteria.
- `CommerceSpec`: only the commerce workflows implied by the task, plus configuration and verification boundaries.
- `VerificationReport`: status, routes, viewports, actions, runtime/network findings, screenshots, limitations, and repair references.
- `RepairPlan`: evidence-linked finding, severity, target, bounded change, and recheck criteria.
- VisualCritique: model-authored strengths and evidence-linked findings tied to the exact route, viewport, and screenshot path received; this is review input, not host-verified approval.

The schemas and durable versioned read/write tools are implemented behind `SELTRA_ORCHESTRATION_ENABLED=1`, with records in each app's git-ignored `.dyad/experiment-2/artifacts/` directory. When enabled, the existing `run_tests` tool writes a host-authored report containing per-spec outcomes and, when `SELTRA_BROWSER_QA_ENABLED=1` and tagged tests provide evidence, route/viewport screenshots and browser measurements. The host report records the exact screenshot paths attached to the model. A critique must review exactly those paths, and a screenshot set can be critiqued only once. A RepairPlan must reference the latest critique ID; Dyad counts host-authored test reports after that plan and blocks the next test batch when its cap (at most three) is exhausted, before reserving attempts or launching tests. Incomplete route/viewport coverage is `blocked`; complete objective evidence remains `needs_review` pending visual review. The model-authored `visual_critique` artifact does not grant visual approval. The Agent tool rejects model-authored `passed` reports and host-attached screenshot claims. Do not make the user app's code, credentials, or arbitrary uploaded contents part of diagnostic logs. Agent failures, timeout, cancellation, and missing optional capabilities must be represented explicitly rather than converted to success.

## Scheduling policy

Use existing read-only Explorer/reviewer agents for independent analysis. Keep application edits serialized through the existing root/Implementer mutation ownership. Do not run code-writing specialists in parallel over overlapping files. Join/cancel child work using the subagent manager lifecycle and preserve its actor/run identity; do not add a second queue, lock, or lifecycle controller.

## Current phase assessment

- Phase 1 primitives are substantially present: bounded root tool loop, task delegation, cancellation, file mutation coordination, plan persistence, and repair capabilities. Automatic mode behavior is already supported by Agent/Build; Plan remains an explicit mode.
- Phase 1's typed artifacts, durable storage, and host-validated implementation-plan progression are implemented. The host checks dependencies before task start, requires evidence on completion, validates status transitions, caps retries at two attempts, preserves active tasks, and refuses overlapping active writer scopes. It returns a disjoint dependency-ready task batch to the root. Business-aware specialist routing, durable run lifecycle status, and the requested Agent/Build/manual-mode/failure/cancellation/concurrency E2E matrix remain incomplete; existing Dyad subagent and operation coordinators remain authoritative.
- Phase 2 has opt-in DesignSpec reasoning, route-required new DesignSpecs, and typed, versioned artifacts. With browser QA enabled, the existing Dyad test runner attaches up to six tagged screenshots to the next agent message with route/viewport/path labels. A new critique must include evidence-backed 1–5 scores across eight visual dimensions for every screenshot; score aggregation is deterministic but does not grant human or host approval. Dyad enforces exact screenshot linkage, RepairPlan linkage/cap, and recheck budgets at artifact/test-run boundaries. A real host-attached critique, generated-app repair/reverification, before/after benchmark, and human review remain incomplete.
- Phase 6 now captures bounded citations and unverified source excerpts from existing search/fetch/crawl tools into a low-confidence ResearchArtifact on writable orchestrated turns. Independent fact verification, design-pattern extraction, asset plans/fallbacks, and research-injection benchmark coverage remain incomplete.
- No claim of Experiment 2 verification or release readiness is made by this document.

- Phase 5 ZIP attachment handling uses Dyad's existing chat attachment pipeline and private media storage. It identifies ZIPs by extension, MIME type, or signature and rejects traversal, symlinks, encrypted/unsupported formats, duplicate names, excessive entry counts, per-entry/total declared expansion, and oversized archives. It does not write extracted files or execute content; only capped, escaped UTF-8 excerpts and a bounded inventory are added to the prompt as untrusted data. Figma API import is implemented and now directs the orchestrated agent to persist the already-imported bounded metadata as a `design_reference`; that artifact handoff is not yet end-to-end verified. Figma image-byte retrieval and the multimodal benchmark remain open.
