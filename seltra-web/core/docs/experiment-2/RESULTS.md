- Artifact contracts cover business briefs, requirements, implementation plans, design specs, commerce specs, content/asset plans, verification reports, repair plans, and research sources. Implementation-plan dependencies are validated for duplicates, unresolved references, and cycles. Verified requirements/integrations require evidence. Agent-authored verification reports cannot claim `passed`; only the host-authored collector can assign the report status, and it currently retains `needs_review` for clean runs pending visual review.
- Artifact persistence caps record size, stores run/message/producer/model provenance, retains versions, checks app/chat identity on reads, and rejects likely credential/private-key values. The root Agent owns writes; delegated writers cannot race artifact updates.
- With orchestration enabled, Dyad's existing `run_tests` tool saves host-parsed per-spec outcomes and tagged browser evidence as a `dyad-test-runner` VerificationReport. Infrastructure and cancellation remain blocked/cancelled, failed tests remain failed, and objective browser failures are reported. Runs missing browser, required route, or mobile/tablet/desktop evidence are blocked; complete objective checks remain `needs_review` pending visual review. The host copies captured PNGs into `.dyad/experiment-2/screenshots/`; the model cannot upgrade this report to passed through its artifact tool.
- Verification reports can carry bounded per-spec outcome counts. Test paths are made app-relative (or reduced to a basename when outside the app), and no test error output is copied into this artifact.
- `SELTRA_DESIGN_INTELLIGENCE_ENABLED=1` independently opts Agent/Build into detailed design reasoning. Both flags default off, preserve Ask/Plan behavior, and continue using Dyad's existing file, test, preview, and repair tools.
- The web test harness now resolves `jose` from the server package and forwards only standard Windows process paths to its isolated gateway child; it does not inherit `.env.web` credentials.
- Chat ZIP attachments remain as the original file in .dyad/media; Dyad recognizes ZIP by extension, MIME type, or signature and validates archive paths/types/sizes and adds a bounded, escaped inventory plus selected UTF-8 text excerpts as explicitly untrusted prompt context.
