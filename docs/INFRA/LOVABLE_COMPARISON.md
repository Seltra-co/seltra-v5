Live browser evidence for T6, recorded on 2026-11-14. Values are approximate only where noted; otherwise, missing measurements are explicitly marked rather than inferred.

## Test prompts

1. `Build a modern, premium ecommerce website for a fashion brand featuring a stylish product gallery, category collections, best sellers, product details, shopping cart, and secure checkout.`
2. `Build a clean portfolio page for a freelance graphic designer featuring a grid gallery, client testimonials, and a contact form.`

The ecommerce prompt was explicitly run as a standalone Seltra storefront, not Shopify. Lovable initially presented its Shopify-oriented setup question; the user overrode that path before the standalone store was built. No Shopify account or store was connected.

### Measurements and evidence notes

- Timestamps in the Seltra dashboard are displayed to the minute. Gateway timestamps show the portfolio workspace request at 17:38:40, plan/build activity beginning around 17:39, verified syncs (81 and later 89 files) by 17:44:55, and preview assets loading at 17:46. Some syncs for that same run failed verification; others later succeeded.
- Seltra's portfolio questionnaire asked, "Who are the main customers for your products, and what design style should the store use?" Its supporting copy referred to storefront/product presentation. Those choices do not fit the portfolio prompt, so the question was skipped rather than answered with invented audience data.
- An earlier Seltra ecommerce attempt was stopped before preview and showed a plan/restore warning. A separate fresh run (`5a4e8b7d-8218-4ed5-8cfb-02575c9733f5`) later rendered its storefront and was reopened with a live preview, but the run itself ended in `COMPLETION_GATE_FAILED`; the earlier attempt should not be confused with this fresh-run evidence.
- After the earlier portfolio reopen 401s, gateway diagnostics later recorded successful ticket redemption, workspace-runtime readiness, and event subscription at 18:05:53. The dashboard subsequently showed the live preview iframe; the initial 401 was transient and its cause was not established.
- The Seltra portfolio preview rendered a four-card work grid, testimonials, and a contact form. The main navigation and native required-field validation responded, but hero/gallery images appeared as blank placeholders. An HMR WebSocket handshake returned 403; app content was still visible in the preview iframe.
- On the latest live dashboard check, the StudioVerge preview iframe rendered its homepage. Six content images reported loaded, the work links worked, and submitting the empty contact form produced browser-required-field errors. This later image/preview state supersedes the earlier blank-image observation.
- The first later reopen from Recent stores showed "You no longer have access to this project" and Retry connection returned 401. On a subsequent gateway restart, the authenticated workspace restored; the preview returned HTTP 200 and its CSP included `'self'`, `localhost:3000`, and `127.0.0.1:3000` with no invalid IPv6 source. The image route probe returned 401 without a model token (rather than the earlier 404), confirming it now reaches the existing auth guard.
- A dashboard reload alone did not restore the preview within 30 seconds. Selecting StudioVerge in Recent restored the live iframe in about 25.2 seconds; the gateway logged a workspace restore and the Core event socket subscribed. The project later displayed "All steps complete 3/3". No replay was observed. The Vite HMR WebSocket still returned 403; public preview HMR is intentionally disabled in the current code, and the preview remained usable.
- Reopened-preview `PerformanceResourceTiming` (not the original prompt-to-preview waterfall): Seltra document TTFB ~1.03 s, DOMContentLoaded ~4.54 s, load ~4.55 s, 65 resource entries (all completed); Lovable portfolio document TTFB ~2.03 s, DOMContentLoaded ~5.17 s, load ~5.93 s, 10 resource entries (all completed).
- Lovable's portfolio completion message said the draft contains nine sample projects, project pages, testimonials, about/contact pages, responsive layouts, and 16 passing automatic checks. It also explicitly said contact messages are not saved and email sending is not configured. On a later cold project reopen, the actual preview rendered Mara Voss's homepage and the `/work` page. The homepage showed four featured projects; `/work` showed two projects and category filters. The draft remained unaccepted.
- Lovable's second portfolio comparison was not completed: the project paused for insufficient credits. The Seltra fresh ecommerce run's HMR page error was fixed in the QA noise classifier and covered by a regression test, but no post-fix live run was captured; the comparison therefore remains incomplete.
- No trace/video recording was available through the shared browser tools. Browser snapshots and a Seltra reopen screenshot were captured. The initial post-prompt first-paint timing and network waterfall remain unmeasured; the later reopen measurements above are not substitutes.

## Replicate in Seltra

- **T5 instant restore + replay:** preserve the plan/chat state, but render an immediately available static preview and replay on reopen; do not leave a blank preview after an app-process exit. Record live-preview readiness separately.
- **T6 no-Shopify parity:** keep the standalone fashion flow and never suggest or auto-select Shopify for this prompt.
- **T9 dynamic questionnaires:** generate questions from the actual prompt and app type. The observed Seltra portfolio prompt received an ecommerce-specific question and storefront copy; the planner prompt and fallback now handle portfolio prompts without commerce language, with regression tests.
- **T10 real-time todos:** show one blueprint-derived checklist and file progress. No file tree or todo progress was visible during initial generation; after gateway restart/reopen, Seltra did show a three-step tracker (`All steps complete 3/3`).
- **T7 image asset routing:** the ecommerce run's `/v1/images/generations` requests returned 404 even though a handler exists at `/images/generations`. Both paths now dispatch to the existing authenticated handler, with regression tests. Keep errors visible if generation fails.
- **Preview CSP:** the browser rejected `http://[::1]:3000` as a `frame-ancestors` source. The policy builder now omits only IPv6 loopback while retaining `'self'` and other configured origins; the CORS allowlist and preview authorization are unchanged. A regression test covers the serialized policy.
- **Workspace sync diagnostics:** preserve strict manifest verification, but expose the verification mismatch detail. The portfolio run had failed and successful syncs, followed by `journal_begin / BACKEND_REJECTED`. Backend logs also recorded ownership-check 403s for workspace-persistence and push-result requests, while other requests succeeded. Resolve the user/workspace identity mismatch from authenticated claims and stored ownership; do not weaken ownership checks or turn failures into success-shaped results.

## Caveats

- The initial post-prompt first-paint timing and full network waterfalls were not captured. Later reopened-preview timings and resource counts are recorded above, but they do not fill those initial-load fields.
- The Seltra portfolio reopened and completed after gateway restart. The reopen took about 25.2 seconds from the Recent click; a direct dashboard reload did not restore it within 30 seconds, and no replay was observed.
- Seltra's first reopen check returned a transient 401 access error. Later gateway diagnostics and the live preview confirm the workspace recovered, but the cause of the earlier 401 is not established.
- Lovable's portfolio preview did reopen; its time-to-visible preview is approximate, while resource timing from the reopened iframe was measured above. No replay animation was observed.
- The HMR WebSocket 403 and workspace-sync verification/ownership errors remain; the preview still rendered and the portfolio completed. The earlier reopen 401 later recovered, but its cause was not established.
- Source validation: gateway route/CSP tests passed (3 tests); planner tests passed (4 tests); gateway typecheck and bundle build passed; backend compile passed. After restart, the gateway CSP response and image-route auth guard were verified live, and frontend, backend, and gateway health checks returned HTTP 200.
