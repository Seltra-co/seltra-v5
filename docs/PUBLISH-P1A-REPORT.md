## 3. Deviations and why

- Amendment A8 requires generating the migration with `prisma migrate dev` against a local staging Postgres. No local staging database was available; the configured `.env` points to Neon. The SQL was generated offline from the checked-in schema to avoid touching Neon. Migration application and the prescribed local-staging generation remain outstanding.
- Exact Neon-branch command to run only after Willy approves and supplies the intended branch configuration: `npm.cmd exec prisma migrate deploy -- --schema prisma/schema.prisma`. This command was **not run**.
- P1A is Backend-only. The public tenant route ownership enforcement and route deletion/restoration are later Core work; this phase establishes the Backend tenant/app ownership fields and state endpoints only.
- `CONFIG_MISSING` for `PUBLISH_PUBLIC_API_URL` belongs at the Core publish entry point: Amendment A1 assigns that variable to Core and excludes it from Backend. Core was not modified in P1A. The Backend currently receives only its specified publish flag, mode, root domain, protected slugs, and quotas.
- Scaffold format check: `WorkspaceSupervisor` passes its configured public API URL unchanged except for removing a trailing slash as `VITE_SELTRA_API_URL`. `seltra-commerce.ts` appends `/storefront/<slug>/...`; Backend routes are under `/api/v5/storefront/...`. Therefore the value must include `/api/v5` (for example `https://seltra-v5-merchant-backend.onrender.com/api/v5`). Current Core runtime config still reads the older `SELTRA_PUBLIC_API_URL`; P1B must switch it to `PUBLISH_PUBLIC_API_URL` and validate its public/local rules.
